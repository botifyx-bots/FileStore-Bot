## ◈ Overview

**File Store Pro** is a production-grade Telegram file-storage bot built with **Pyrofork** and **MongoDB**. It stores files in private DB channels and delivers them through encoded, expiring links — complete with force-subscription gates, a premium credit system, quality-grouped batch links, and a full channel post manager.

## ✦ FBatch — Quality Link Flow

```
Admin: /fbatch
       │
       ├─ Forward first DB-channel message (or send link)
       ├─ Forward last DB-channel message
       │
       └─ Bot scans the full range:
               ├─ Groups files by Season then Quality
               │     Quality order: 360p < 480p < 720p < 1080p < 4K < HD < HDRip < BluRay
               ├─ Saves each group to MongoDB  →  fbatch_XXXXXXXXXXXXXXXX
               ├─ Encodes each batch ID (base64, identical to /batch and /genlink)
               └─ Sends admin a copyable code block:

                   SEASON: S01 :~
                   ✧480p✧ - t.me/bot?start=Zmj... | ✧720p✧ - t.me/bot?start=Zmj...
                    ✧1080p✧ - t.me/bot?start=Zmj...

                   SEASON: S02 :~
                   ✧480p✧ - t.me/bot?start=Zmj... | ✧720p✧ - t.me/bot?start=Zmj...

User clicks a quality link:
       ├─ Ban check → Premium check → Shortener/Credit check
       ├─ Info card  (custom_pic + Anime · Season · Audio · Quality · Episodes)
       ├─ Start sticker
       ├─ All files for that quality group
       ├─ End sticker
       └─ Auto-delete countdown begins
```

## ◆ Custom Buttons — Bot-Wide File Buttons

Reachable from **Settings → ✎ Custom Buttons**, or send `/tokensettings` for the credits side of things.

```
Settings → ✎ Custom Buttons → ✎ Set Buttons
  │
  ├─ Bot sends the format prompt:
  │     Button text 1 - http://example.com/
  │     Button text 2 - http://example2.com/
  │     (use | for up to 2 buttons per row)
  │
  ├─ Send your buttons in that format  →  parsed, validated, saved instantly
  ├─ Send 0                            →  cancel, back to the home menu
  └─ Nothing sent within 2 minutes     →  auto-aborts
```

Once set, these buttons are automatically appended under **every file** delivered through `/genlink`, `/batch`/`/nbatch`, and `/fbatch` links — stacked underneath that file's own buttons (if it has any), never replacing them. Toggle `PROTECT`/`DISABLE_BTN` in Settings to suppress all buttons (original + custom) at once. Use **🗑 Clear Buttons** to remove them.

## ⌗ Token / Credits Settings

Reachable from **Settings → 🪙 Tokens/Credits**, or `/tokensettings` directly.

| Setting | Default | What it controls |
|---|---|---|
| Starting credits | `5` | Credits a brand-new user starts with |
| Verification reward | `5` | Credits granted per completed shortener verification |
| Anti-bypass min time | `45s` | A "verification" faster than this is rejected as a bypass |
| Verification link expiry | `240s` | How long a verification deep-link stays valid |

All four apply instantly — no restart needed — and every value you enter is validated (whole numbers only, and the anti-bypass window must stay smaller than the expiry window). `/checktoken <user_id>` shows whether a specific user's verification token is currently valid, too-early, or expired, plus their credit balance.

## ✧ Recent Fixes & Improvements

<details>
<summary><b>Click to expand — settings persistence, correctness fixes, and new features</b></summary>

**Settings now persist across restarts** — `client.messages` (start/fsub/about/channels/reply text, start/fsub photos), `client.protect`, `client.auto_del`, and the admin list previously lived in memory only and silently reverted to `config.py` on every restart. All four are now saved to MongoDB the moment they're changed through Settings, `/add_admin`, `/rm_admin`, or the Texts/Photos panels, and reloaded on boot.

**`/fbatch` range scanning is now chunked** — large ranges (e.g. a full season, 300+ episodes) were fetched in a single `get_messages` call, silently hitting Telegram's 200-id limit and truncating results. Now scanned in chunks of 200 with `FloodWait` handling.

**`/ban` and `/unban` no longer abort on one bad ID** — previously, a single malformed ID anywhere in the list would stop the whole command after only partially applying it, with a generic error and no indication of what actually happened. Each ID is now handled independently; the reply shows how many succeeded and lists any that were skipped.

**Shortener calls no longer block the bot** — `plugins/shortner.py` used synchronous `requests.get()` (including one call with no timeout at all) directly inside async handlers, which could freeze the entire bot for every user if the shortener API was slow or hung. Converted to non-blocking `aiohttp` calls with timeouts throughout.

**`/stats` no longer freezes the bot for ~2 seconds** — the CPU-usage calls (`psutil.cpu_percent(interval=1)`, called twice) ran synchronously in the event loop. Now offloaded to a thread via `asyncio.to_thread`.

**Removed a duplicate settings handler** — two different files each registered a handler for the same Settings → Texts button, so it fired twice on every tap and could show stale/incorrect content. The outdated copy was removed.

**Two new configurable systems added** — see [Custom Buttons](#-custom-buttons--bot-wide-file-buttons) and [Token / Credits Settings](#-token--credits-settings) above; both were previously hardcoded and only changeable by editing code and redeploying.

**Full text/formatting pass** — bot-wide small-caps + text-symbol styling (`✓ ✗ ✦ ✎ ›› •`) in place of mixed plain English and picture emoji, and `<blockquote>`/`<b>` wrapping added to messages that were previously bare text.

</details>
